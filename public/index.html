Why RIMBUX

Verify First. Execute Safely.

THE PROBLEM

AI agents now hold the keys

AI agents can initiate payment workflows on your behalf. A malicious prompt, an untrusted destination, or an unsafe policy change can put wallet funds at risk. An LLM should not be the authority that approves its own payment actions.

THE SOLUTION

A deterministic firewall, not a prompt

A deterministic policy engine—not the LLM—evaluates each structured payment intent against spending limits, destination rules, and rule-based threat indicators. Intents that meet the configured threshold are held for operator approval.

HOW IT WORKS
  1. Parse — Convert the agent instruction into a structured payment intent.
  2. Evaluate — Check spending policies, available reputation signals, and rule-based threat indicators.
  3. Authorize — The backend returns a decision for each intent: ALLOW, REQUIRE_APPROVAL or BLOCK.
  4. Dry-run signer — Produce a payload digest and a simulated signing status. No NEAR transaction is signed or broadcast.

Defense-in-Depth Threat Model

Intended layers: off-chain firewall, scoped FunctionCall key and on-chain vault contract. This page exercises the first two; the vault contract code is not inspected here.

Layer 1 // Off-Chain AI Firewall
Pre-Signing Scam & Injection Shield

Blocks prompt-injection overrides, multi-recipient parameter smuggling, and Levenshtein/homoglyph typosquatting before any authorization is granted.

Layer 2 // FunctionCall Key Scope
FunctionCall-Only Key Scope

The agent uses a restricted FunctionCall key for execute_agent_payment with zero native deposit. Receiver, permission, verification status, and gas allowance are reported dynamically from the backend and NEAR Testnet RPC; no fixed allowance is assumed.

Layer 3 // On-Chain Vault Contract
Deterministic Contract Enforcement

Design target: the configured vault contract is intended to enforce per-tx caps, 24h daily quotas and allowlisted recipients on-chain, even if the agent runtime is compromised. This page does not inspect the contract.
